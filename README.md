## 1. Тема и основной пользовательский сценарий

- **Тема проекта**: Каталог фильмов и сериалов — просмотр, оценки и избранное.
- **Целевой пользователь**: Любитель кинематографа, желающий упорядочить свои просмотры и находить новое кино.
- **Основной сценарий**: Приложение помогает пользователю вести персональную медиатеку в облаке. Пользователь может зарегистрироваться или войти со своей учетной записью, просматривать каталог кинокартин и сериалов, фильтровать их по статусу («В планах», «Смотрю», «Просмотрено»), открывать подробную карточку конкретного фильма, создавать новые записи через валидируемую форму с выбором жанра из базы данных Supabase, редактировать существующие данные и удалять фильмы с подтверждением. Данные надежно сохраняются при перезагрузке и изолированы между аккаунтами.

## 4. Схема данных в PostgreSQL (Supabase)

Схема создается через миграции `supabase/migrations/` и наполняется через `supabase/seed.sql`:

1. **Таблица `public.genres` (публичный справочник):**
   - `id text primary key` — строковый идентификатор без пробелов (`sci-fi`, `drama`, `crime` и др.);
   - `name text not null unique` — название жанра на русском языке;
   - **Доступ**: RLS включен, ролям `anon` и `authenticated` выдан `GRANT SELECT` с политикой `using (true)`. Запись запрещена.

2. **Таблица `public.media_entries` (основная сущность пользователя):**
   - `id uuid primary key default gen_random_uuid()`;
   - `owner_id uuid not null references auth.users(id) on delete cascade` — внешний ключ к пользователю;
   - `genre_id text not null references public.genres(id) on update cascade on delete restrict`;
   - `title text not null` (CHECK: длина от 2 до 100 знаков);
   - `original_title text not null default ''`;
   - `description text not null default ''`;
   - `type text not null` (CHECK: `'movie'` или `'series'`);
   - `release_year integer not null` (CHECK: 1895–2100);
   - `rating numeric(3, 1) not null` (CHECK: 1.0–10.0);
   - `status text not null` (CHECK: `'planned'`, `'watching'`, `'watched'`);
   - `priority text not null` (CHECK: `'low'`, `'medium'`, `'high'`);
   - `duration_or_episodes text not null default ''`;
   - `director_or_creator text not null default ''`;
   - `created_at timestamptz not null default now()`;
   - **Доступ (ЛР 6)**: RLS включен, роли `authenticated` выданы права `SELECT, INSERT, UPDATE, DELETE` с 4 строгими политиками по условию `auth.uid() = owner_id`. Пользователь может читать, создавать, изменять и удалять исключительно свои личные записи.

## 5. Маршруты приложения

В проекте настроена клиентская навигация SPA (Single Page Application) без перезагрузки страниц:

| Маршрут | Описание | Компонент |
| :--- | :--- | :--- |
| `/` | Перенаправление на каталог | `<Navigate to="/movies" replace />` |
| `/movies` | Список фильмов с фильтрацией по статусу просмотра | `<MoviesPage />` |
| `/movies/:id` | Подробная карточка фильма по ID с кнопками редактирования и удаления | `<MovieDetailsPage />` |
| `/movies/new` | Экран создания новой картины с сетевой формой | `<NewMoviePage />` |
| `/movies/:id/edit` | Экран редактирования картины с предзаполненной сетевой формой | `<EditMoviePage />` |
| `/login` | Вход и регистрация учетной записи в Supabase Auth | `<LoginPage />` |
| `/movies/missing` | Обработка отсутствующей записи по ID | `<MovieDetailsPage />` (сообщение «Фильм не найден») |
| `*` (любой другой) | Страница ошибки 404 (неизвестный адрес) | `<NotFoundPage />` |

*Все страницы отображаются внутри общего макета `<AppLayout />` со сквозной шапкой, навигацией, профилем пользователя и облачным статусом хранения.*

## 6. Инструкция по установке и запуску

Все команды выполняются из терминала.

### 6.1. Запуск в режиме разработки (Dev)

Из корня репозитория:
```bash
cd frontend
npm ci
npm run dev
```
После запуска откройте в браузере локальный адрес (по умолчанию: `http://localhost:5173`).

### 6.2. Проверка сборки (Production Build) и предпросмотр (Preview)

Перед фиксацией изменений или сдачей работы проверьте строгую компиляцию типов и сборку:
```bash
cd frontend
npm run build
npm run preview
```
Команда `npm run build` выполняет проверку типов TypeScript (`tsc -b`) и оптимизированную сборку в каталог `frontend/dist`.  
Команда `npm run preview` запускает локальный статический сервер для просмотра готовой сборки.
